Подключены в текущей реализации

  - basePara.calcAssign — подключен как верхнеуровневый флаг выполнения assignment pipeline: при True выполняется preprocessing/search/choice/split, при False расчет assignment отключается до preprocessing/search/choice/split.
  - basePara.calcSkimMatr — управляет построением skim-матрицы как доменной проекции над результатами choice/split.
  - skimMatrixPara.func — задает правило агрегации skim-атрибутов: Mean или Quantile.
  - skimMatrixPara.volumeWeighted — задает веса агрегации: пассажиропоток по доле спроса или равный вес альтернатив.
  - skimMatrixPara.quantile — квантиль для режима Quantile.
  - skimMatrixPara.lowImpConnShare — доля выбранных соединений с минимальным split_impedance, включаемых в skim-агрегацию.
  - basePara.preAssignPeriod — подключен как доменная конфигурация периода назначения для admissibility complete connections; входная единица неоднозначна, в коде временно зафиксирована как минуты.
  - basePara.postAssignPeriod — подключен как доменная конфигурация периода назначения для admissibility complete connections; входная единица неоднозначна, в коде временно зафиксирована как минуты.
  - choicePara.deleteConnsOutsideAssignmentPeriod — подключен как флаг удаления complete connection до dominance retention.
  - choicePara.deleteConnsWithDepBeforeAssPeriodForDepBasedDSeg — подключен как флаг удаления departure-based complete connection до dominance retention.
  - choicePara.deleteConnsWithArrAfterAssPeriodForArrBasedDSeg — подключен как флаг удаления arrival-based complete connection до dominance retention.
  - splitPara.depBasedDSeg — подключен как выбор временной основы demand segment для admissibility-фильтра и split temporal utility: departure/arrival.
  - splitPara.considerConnsWithPosDeltaT — подключен как флаг admissibility-фильтра complete connections.
  - splitPara.choiceModel — подключен как выбор модели распределения спроса между выбранными соединениями.
  - splitPara.KirchhoffExp — подключен как exponent для choiceModel = Kirchhoff.
  - splitPara.logitExp — подключен как exponent для choiceModel = Logit.
  - splitPara.BoxCoxExp — подключен как exponent для choiceModel = BoxCox.
  - splitPara.BoxCoxTransformImp — подключен как флаг преобразования split impedance перед вычислением веса выбора.
  - splitPara.BoxCoxPara — подключен как параметр t преобразования Box-Cox для splitPara.BoxCoxTransformImp.
  - Independence.useIndependence — подключен как флаг включения коэффициента независимости похожих альтернатив в split-модели.
  - SearchImp.volCapRatioFactor — читается в SearchImpedance.volume_capacity_ratio; положительное значение хранится в runtime-конфигурации как stored_only и не включает capacity-aware search без явного включения режима enabled.
  - PerceivedJourneyTime.volCapRatioFactor — читается и хранится в PerceivedJourneyTimeWeights.volume_capacity_ratio; положительное значение включает capacity-aware split и применяется в итерационном fixed-point/MSA слое при наличии veh_journey_item_cap.csv.
  - searchPara.allowDominanceForEquivalentConnections — подключен как флаг partial-search retention между эквивалентными состояниями поиска.
  - searchPara.deactivateDominanceOfDirectConnections — подключен как флаг complete-connection dominance: прямое полное соединение не может доминировать другие complete connections и suffix lower-bound candidates.
  - searchPara.ToleranceConstraints.minSearchImpAbs/minJourneyTimeAbs — входные абсолютные допуски трактуются как минуты и нормализуются в секунды перед построением SearchTolerances.
  - choicePara.ToleranceConstraints.minSearchImpAbs/minJourneyTimeAbs — входные абсолютные допуски трактуются как минуты и нормализуются в секунды перед построением ChoiceTolerances.
  - searchPara.TemporalSuitability.minTWT/maxTWT — входные значения трактуются как минуты и нормализуются в секунды перед построением TransferLimits.
  - searchExecution.formulation — необязательный высокоуровневый режим постановки расчета: demand_task_assignment сохраняет прежний OD-интервальный demand-driven режим, od_day_assignment задает требуемую постановку "один service-day tree на origin и OD-day alternatives", all_zone_search включает search-only enumeration для всех объявленных зон, timed_connection_diagnostics включает старый timed demand-task контур только как диагностический режим.
  - searchExecution.partialRetentionScope — необязательный ключ режима partial-retention: tree_global задает целевую article-like реализацию с общей pruning-памятью дерева, projection_slot_local сохраняет прежний консервативный per-projection-slot режим.
  - searchExecution.maxParallelBatches — необязательный положительный целый лимит параллельных origin/batch worker-ов для tree-level search; по умолчанию 6.
  - searchExecution.validatePhaseInvariants — необязательный диагностический флаг: при True включает дорогую проверку фазовых инвариантов каждой принятой ветви; при отсутствии ключа используется False.
  - searchExecution.logProjectionDetails — необязательный диагностический флаг: при True включает подробный лог по каждому projection slot; при отсутствии ключа используется False.
  - veh_journey_item_cap.csv — подключен как необязательный вход провозной способности vehicle journey items для post-assignment overload assessment.
  - compile-time runtime override policy — подключена как отдельный верхнеуровневый слой после загрузки входа и до запуска assignment pipeline; применяется только если сборка выполнена с TIMETABLE_ENABLE_RUNTIME_OVERRIDES.

OD-day day-level path set:

  - SearchConnection остается конкретным расписательным соединением с trip/time information;
  - DayPathSignature задает дневной структурный путь между районами: access/transfer/egress walk и ride legs по route segment / line / route / stop-occurrence структуре, без connection segment id, trip id и clock time;
  - DayPathPrefix является инкрементальной структурной подписью ветви поиска: она накапливается при каждом walk/ride extension и проверяется на совпадение с финальной DayPathSignature при завершении OD-пути;
  - OD-day computational contract = incremental_day_path_retention: tree-level pruning в этом режиме использует ключ (DayPathPrefix, continuation-safe search state), поэтому timed supports одного структурного prefix начинают схлопываться внутри дерева, а не только после materialized complete connection;
  - рабочие day-path search states отделены от финальных OD alternatives: TreePartialRetention хранит раннюю pruning-память по prefix/state, SearchProjectionRetention хранит только завершенные DayPathRetention для OD-пары;
  - DayPathRetention индексирован по DayPathSignature; финальный vector<DayPathAlternative> создается только на finalize-границе и остается детерминированно упорядоченным по структурной подписи;
  - OD-day search требует formulation = od_day_assignment, diagnostic_mode = false и partialRetentionScope = tree_global; projection_slot_local остается только для legacy/diagnostic timed-постановок;
  - для OdDayPairs найденный complete timed support сразу проецируется в DayPathSignature и удерживается в DayPathRetention; сырые complete timed alternatives не становятся состоянием OD-day result slot;
  - timed connections с одинаковой DayPathSignature схлопываются в один representative SearchConnection уже внутри search slot retention, а не поздним постпроцессингом после complete-connection retention;
  - представитель пути выбирается по доменной политике лучшего timed support: exact dominance, затем меньший impedance, меньшее journey time, меньше transfers, более ранний arrival и более поздний departure;
  - search_connection_count в OD-day output после этого слоя считается количеством day-level path representatives, а не количеством raw timed connections.
  - OD-day choice/split consume DayPathAlternative entities; SearchConnection remains only the representative timed support used for metric projection, segment loads and existing output compatibility;
  - OD-day choice applies day-path retention/tolerance and treats duplicate day-path signatures in search output as an invariant violation; complete-connection retention remains only in the legacy timed DemandTasks formulation;
  - DayPathMetrics separates complete-retention metrics from representative connection metrics, so split/admissibility no longer reinterprets raw timed connections as primary OD-day alternatives;
  - assignment diagnostics are explicit counters over alternatives; legacy search_connection_count/chosen_connection_count fields are compatibility projections.
  - elementary segment loads in OD-day assignment require day-path split shares; timed connection shares are accepted only by the legacy/diagnostic demand-task formulation;
  - OD-day pipeline validates that every split share is sourced from DayPath before elementary_segment_loads is materialized as the primary load contour;
  - VISUM route/stop aggregates in OD-day assignment are built from day-path split shares and representative timetable support; they are aggregate comparison projections, while elementary segment loads remain the primary load representation;
  - AssignmentOutput хранит elementary_segment_loads как основной sparse-профиль нагрузки; loads.route_total_loads и loads.stop_total_loads являются VISUM-сравнительными агрегатами, а vehicle_journey_item_loads является overload assessment над тем же elementary support;
  - overload assessment рассчитывается только из elementary_segment_loads и capacity rows; пересчет overload напрямую из OD alternatives, route aggregates или stop aggregates запрещен инвариантами output validation;
  - the old timed demand-task calculation is preserved as searchExecution.formulation = timed_connection_diagnostics (equivalent search contract to demand_task_assignment, intended for diagnostics/comparison rather than the required OD-day formulation); runtime logs mark such execution as diagnostic.

Семантика skimMatrixPara.lowImpConnShare:

  - для OD-интервала берется множество альтернатив после выбора и распределения спроса;
  - альтернативы сортируются по возрастанию split_impedance;
  - сохраняется ceil(lowImpConnShare * n) альтернатив, где n — число альтернатив с положительным весом;
  - если lowImpConnShare > 0 и n > 0, сохраняется не менее одной альтернативы;
  - volumeWeighted не влияет на отбор альтернатив, а используется только внутри агрегации значений.

Выход skim:

  - доменный результат хранится в AssignmentOutput.skim_matrix;
  - skim зависит от assignment-result: матрица строится только при calcAssign = True, потому что использует результаты choice/split;
  - если calcSkimMatr = False, AssignmentOutput.skim_matrix.status = disabled_by_config;
  - если calcSkimMatr = True и calcAssign = False, AssignmentOutput.skim_matrix.status = skipped_assignment_disabled, entries остается пустым;
  - если calcSkimMatr = True и calcAssign = True, AssignmentOutput.skim_matrix.status = calculated, entries содержит рассчитанные OD-интервальные строки;
  - JSON содержит секцию skim_matrix со status и entries;
  - файловый экспорт содержит отдельный файл skim_matrix.csv.

Семантика basePara.calcAssign:

  - параметр читается из basePara и хранится в AssignmentExecutionConfig отдельно от SearchParams;
  - pair-file режим без params.txt использует дефолт calcAssign = True;
  - при calcAssign = True публичный AssignmentOutput имеет mode = calculated;
  - при calcAssign = False публичный AssignmentOutput имеет mode = assignment_disabled;
  - disabled output сохраняет OD-интервальную структуру входного спроса и total_demand_passengers, но search_connection_count, chosen_connection_count, demand_share_count, assigned_passengers, loads и skim entries остаются нулевыми/пустыми;
  - assignment_output.json содержит верхнеуровневое поле mode;
  - assignment_summary.txt содержит mode и skim status;
  - metadata.csv содержит mode, skim_status и основные счетчики результата;
  - существующие аналитические CSV остаются совместимыми по набору колонок.
  - validation запрещает противоречивые результаты: disabled output не может содержать рассчитанные соединения, split shares, passenger loads, vehicle journey item loads или calculated skim; calculated output не может иметь skim_status = skipped_assignment_disabled или vehicle journey item overload status = skipped_assignment_disabled.

Семантика compile-time runtime override policy:

  - compile-time override является слоем эффективной runtime-конфигурации, а не частью математической модели search/split;
  - макросы изолированы в include/timetable/config/runtime_override_policy.hpp и не используются внутри алгоритмических функций;
  - params.txt сначала читается как runtime-намерение пользователя, затем чистая функция apply_runtime_override_policy строит эффективный AssignmentInput;
  - индивидуальные override-флаги действуют только при включенном главном CMake option TIMETABLE_ENABLE_RUNTIME_OVERRIDES;
  - TIMETABLE_OVERRIDE_DISABLE_CAPACITY_AWARE_ASSIGNMENT принудительно отключает behavioral capacity-aware assignment:
      capacity_aware_split_enabled = false,
      PerceivedJourneyTime.volCapRatioFactor = 0,
      SearchImp.volCapRatioFactor при положительном значении остается stored_only и не меняет search;
  - TIMETABLE_OVERRIDE_DISABLE_VEHICLE_JOURNEY_ITEM_OVERLOAD_ASSESSMENT принудительно отключает post-assignment overload assessment без отключения основного assignment pipeline;
  - готовые presets для такого режима: release-no-capacity-stages, local-release-no-capacity-stages, wsl-release-no-capacity-stages, local-wsl-release-no-capacity-stages;
  - compile-time override имеет приоритет над params.txt и предназначен для воспроизводимых экспериментальных конфигураций, когда нужно быстро исключить отдельную стадию без правки входных параметров.

Семантика basePara.preAssignPeriod/basePara.postAssignPeriod:

  - параметры читаются из basePara и хранятся в AssignmentPeriodConfig отдельно от SearchParams;
  - входные значения временно трактуются как минуты: kAssignmentPeriodInputUnit = AssignmentPeriodUnit::Minutes;
  - при переключении кода на AssignmentPeriodUnit::Seconds значения будут трактоваться как секунды без изменения params.txt;
  - доменная модель валидирует конечность и неотрицательность обоих периодов;
  - для demand-интервала [start, end] жесткое окно назначения спроса равно [start - preAssignPeriod, end + postAssignPeriod];
  - search task для branch-and-bound по умолчанию сохраняет окно первого timed departure равным самому demand-интервалу [start, end] для interval-local поиска; в origin-period режиме дерево может иметь более широкий search-time domain, а итоговая принадлежность соединения demand-интервалу определяется отдельным окном назначения спроса;
  - расширение search-time domain должно подключаться только через отдельную SearchTimeDomainConfig/SearchTimePaddingPolicy, потому что это меняет множество перечисляемых альтернатив и вычислительную сложность search;
  - при текущей единице Minutes значение postAssignPeriod = 24*60 означает +1440 минут = +86400 секунд в окне назначения спроса; оно не должно неявно расширять search tree;
  - complete connections проверяются до помещения в dominance retention: reference_time должен попадать в окно назначения спроса, а затем применяются дополнительные флаги удаления из choicePara/splitPara;
  - перед choice выполняется защитная повторная фильтрация тем же demand-segment-предикатом;
  - validation search/choice проверяет, что в результирующих task_results не осталось соединений вне окна назначения спроса или запрещенных дополнительными admissibility-флагами;
  - если задан флаг удаления, не соответствующий текущей основе demand segment, preprocessing выдает предупреждение;
  - SearchTimePaddingPolicy остается отдельной моделью для search-time-domain planning/optimization и не смешивается с AssignmentPeriodConfig.

Семантика временных параметров поиска и абсолютных допусков:

  - для VISUM-подобного params.txt значения searchPara.TemporalSuitability.minTWT/maxTWT, searchPara.ToleranceConstraints.minSearchImpAbs/minJourneyTimeAbs и choicePara.ToleranceConstraints.minSearchImpAbs/minJourneyTimeAbs трактуются как минуты;
  - доменная константа kSearchTemporalParameterInputUnit = SearchTemporalParameterUnit::Minutes задает это поведение по умолчанию;
  - при парсинге эти значения умножаются на 60 и сохраняются во внутренней модели в секундах или секундно-согласованных единицах generalized cost;
  - minNumberTransfersAbs не является временной величиной и не умножается на 60;
  - множители minSearchImpFactor/minJourneyTimeFactor/minNumberTransfersFactor также не меняются, потому что они безразмерны;
  - диагностика params.txt выводит нормализованные min_transfer_wait_sec, max_transfer_wait_sec, search_abs_tol(imp/jt) и choice_abs_tol(imp/jt), чтобы по логу было видно, какие значения реально использует расчет.

Семантика splitPara.depBasedDSeg и delta_t:

  - splitPara.depBasedDSeg = 1 задает departure-based demand segment: интервал спроса относится ко времени отправления соединения;
  - splitPara.depBasedDSeg = 0 задает arrival-based demand segment: интервал спроса относится ко времени прибытия соединения;
  - в split temporal utility departure-based режим использует reference_time = departure_time;
  - в split temporal utility arrival-based режим использует reference_time = arrival_time;
  - раннее отклонение temporal utility считается как max(0, interval.start - reference_time);
  - позднее отклонение temporal utility считается как max(0, reference_time - interval.end);
  - admissibility delta_t имеет направленный смысл для фильтра considerConnsWithPosDeltaT:
      Departure: delta_t = departure_time - interval.end, положительное значение означает отправление после конца интервала;
      Arrival: delta_t = interval.start - arrival_time, положительное значение означает прибытие до начала интервала;
  - если splitPara.considerConnsWithPosDeltaT = 0, соединения с положительным delta_t удаляются;
  - SearchTimePaddingPolicy, admissibility-фильтр и split temporal utility используют совместимую основу demand segment, но остаются отдельными доменными механизмами.

Семантика splitPara.choiceModel:

  - модель хранится в доменной конфигурации SplitChoiceModelConfig: model, exponent;
  - аргумент IMP* предварительно получается из raw IMP через SplitImpedanceTransformConfig;
  - Kirchhoff использует лог-вес log(IND) - exponent * log(IMP*);
  - Logit использует лог-вес log(IND) - exponent * IMP*;
  - BoxCox использует лог-вес log(IND) - exponent * IMP*, где Box-Cox-преобразование самого аргумента включается отдельным флагом BoxCoxTransformImp;
  - LohseExp читается только вместе с choiceModel = Lohse, но runtime validation явно отклоняет Lohse до реализации и утверждения формулы;
  - validation split проверяет, что exponent конечный и положительный, BoxCoxPara конечен, а модель поддержана текущим runtime.

Семантика splitPara.BoxCoxTransformImp:

  - доменная семантика зафиксирована отдельно от choiceModel: choiceModel выбирает семейство весов распределения спроса, а BoxCoxTransformImp управляет преобразованием аргумента IMP перед вычислением веса;
  - BoxCoxTransformImp = 0 означает использование стабилизированного raw IMP без Box-Cox-преобразования;
  - BoxCoxTransformImp = 1 означает применение box_cox_transform(IMP, t), где t берется из BoxCoxPara;
  - для этой политики введена доменная модель SplitImpedanceTransformConfig: boxcox_transform_enabled, boxcox_t;
  - parser читает BoxCoxTransformImp и BoxCoxPara в SplitImpedanceTransformConfig, factory и validation проверяют конечность boxcox_t;
  - split pipeline считает raw split impedance, затем применяет transform_split_impedance, после чего передает полученный аргумент в split_choice_log_weight;
  - output-поле split_impedance остается raw-значением, потому что transform относится к вычислению веса выбора, а не к исходной метрике сопротивления.

Семантика Independence.useIndependence:

  - параметр читается из root.splitPara.Independence.useIndependence и хранится в SplitIndependenceConfig.enabled внутри SplitParams;
  - если useIndependence = 1, коэффициент IND(c) рассчитывается по формуле статьи через параметры gamma, indepMaxDelta, indepHigherPjtCoeff, indepLowerPjtCoeff, indepHigherFareCoeff и indepLowerFareCoeff; поля Higher применяются, когда сравниваемое соединение c' лучше базового c по PJT или fare;
  - старые поля indepHigherQualityCoeff и indepLowerQualityCoeff сохраняются как fallback для старых params.txt: при отсутствии новых полей они используются одновременно для шкал PJT и fare;
  - если useIndependence = 0, чистая функция split_independence(config, alternatives, index) возвращает IND(c) = 1.0 для каждой альтернативы;
  - при IND(c) = 1.0 член log(IND) равен нулю, поэтому independence не влияет на Kirchhoff, Logit и BoxCox веса выбора;
  - output остается стабильным: shares.csv и assignment_output.json по-прежнему содержат поле independence, которое при отключенном флаге равно 1.0;
  - validation split проверяет числовые параметры independence на конечность и допустимые диапазоны даже при useIndependence = 0, чтобы params.txt оставался валидным целиком.

Семантика searchPara.allowDominanceForEquivalentConnections:

  - параметр читается из searchPara и хранится в EquivalentConnectionDominanceConfig внутри SearchPruningModelConfig;
  - параметр управляет только partial-search retention между эквивалентными состояниями поиска; он не относится к complete-connection dominance и не влияет на choice-retention;
  - searchPara.useLastStopForEquivalentConnections читается из searchPara и выбирает stop-reference компонент того же equivalent-state ключа;
  - при useLastStopForEquivalentConnections = 0 ключ использует CurrentStopOccurrence, то есть текущую stop occurrence ветви;
  - при useLastStopForEquivalentConnections = 1 ключ использует LastTimedStopOccurrence, то есть arrival occurrence последнего рейсового сегмента, с консервативным fallback на CurrentStopOccurrence до первой timed-посадки;
  - SearchPruningExecutionPlan переносит EquivalentConnectionDominanceConfig в исполнимый pruning plan;
  - ключ search-pruning строится чистыми функциями equivalent_connection_stop_occurrence и make_search_pruning_state_key из SearchPruningStateProjection без доступа к внутренним branch-структурам search engine;
  - при allowDominanceForEquivalentConnections = 1 включается текущий state-local search pruning: exact dominance и approximate retention внутри extension-safe equivalent state;
  - при allowDominanceForEquivalentConnections = 0 state-local pruning retention отключается, потому что текущая approximate retention использует тот же equivalent-state набор, что и exact dominance;
  - поддержанные stop-reference семантики — CurrentStopOccurrence и LastTimedStopOccurrence: сравнение разрешается только внутри выбранного extension-safe equivalent state;
  - validation запрещает неизвестный stop-reference и проверяет, что при allowDominanceForEquivalentConnections = 0 execution plan не включает exact/approximate retention layers;
  - диагностика search-pruning выводит equivalent_dominance, equivalent_stop_reference, use_last_stop_for_equivalent_connections, retention_requested и retention_suppressed_by_equivalent_dominance.

Семантика searchExecution.partialRetentionScope:

  - searchExecution.formulation является preset-слоем над отдельными полями searchExecution.mode/originScope/timeDomainSource/destinationScope/resultProjection/partialRetentionScope/maxParallelBatches;
  - если одновременно заданы formulation и отдельные поля searchExecution, сначала применяется formulation, затем явно указанные поля уточняют полученную конфигурацию;
  - для требуемой постановки использовать searchExecution.formulation = od_day_assignment; это разворачивается в origin_period + declared_zones + service_day + declared_zones + od_day_pairs + tree_global + maxParallelBatches = 6;
  - параметр относится к SearchExecutionConfig и не меняет множество origins, completion targets или result projection;
  - tree_global задает целевую branch-and-bound семантику статьи: partial-prefix relevance проверяется один раз в рамках дерева по extension-safe search state;
  - complete-connection retention остается projection-local, потому что завершенные альтернативы материализуются отдельно для каждого demand task или completion target;
  - projection_slot_local сохраняет прежний консервативный режим, где partial-prefix retention хранится отдельно для каждого projection slot;
  - при отсутствии ключа CompletionTargets и OdDayPairs по умолчанию используют tree_global, DemandTasks по умолчанию использует projection_slot_local;
  - текущая реализация разрешает tree_global для tree-level projections CompletionTargets и OdDayPairs; DemandTasks остается projection_slot_local;
  - для CompletionTargets после destination-specific suffix lower-bound pruning активные completion targets дополнительно сужаются до оставшихся projection slots, поскольку target и projection slot взаимно однозначны.
  - all-zone CompletionTargets использует count-only result sink: после финализации retention/tolerance для target сохраняется только число найденных полных соединений, а материализованные SearchConnection освобождаются; это не меняет поиск, dominance или итоговые счетчики output.

Семантика searchExecution.validatePhaseInvariants:

  - параметр относится к диагностике SearchExecutionConfig и не меняет множество допустимых переходов, pruning, dominance, lower-bound отсечения или materialization результата;
  - при True общий branch-and-bound цикл проверяет фазовые инварианты корневой ветви и каждого принятого кандидата после расширения;
  - при False эти проверки не выполняются, что является производительным режимом по умолчанию для больших all-zone запусков;
  - ключ может задаваться как булево значение True/False или как числовое 1/0;
  - если блок searchExecution отсутствует, используется дефолт требуемой OD-day постановки:
      origin_period, declared_zones, service_day, declared_zones, od_day_pairs,
      partialRetentionScope = tree_global, maxParallelBatches = 6,
      validatePhaseInvariants = False и logProjectionDetails = False;
  - рабочий params.txt явно фиксирует этот дефолт через searchExecution.formulation = od_day_assignment и технические параметры maxParallelBatches = 6, validatePhaseInvariants = 0, logProjectionDetails = 0;
  - если блок searchExecution присутствует частично, неуказанные поля берутся из дефолтного режима
    требуемой OD-day постановки; явное поле mode меняет только mode, не переключая resultProjection
    и остальные поля постановки.
  - для постановочного запуска технически допустимо менять maxParallelBatches, validatePhaseInvariants
    и logProjectionDetails; изменение originScope/timeDomainSource/destinationScope/resultProjection
    меняет математическую постановку и должно использоваться только как явная диагностика, предпочтительно
    через formulation = timed_connection_diagnostics или all_zone_search.

Семантика searchExecution.logProjectionDetails:

  - параметр относится только к детализации журнала SearchExecutionConfig и не меняет допустимые соединения, pruning, dominance, choice/split или загрузки;
  - при True после каждого origin-tree дополнительно пишется строка по каждому OD projection slot;
  - при False сохраняются batch-level summary и heartbeat-диагностика, но OD-day-прогон не пишет 51529 подробных projection-строк.

Формализованы как отдельная доменная политика complete-connection dominance

  - searchPara.deactivateDominanceOfDirectConnections — относится к dominance полных соединений в CompleteConnectionRetention, а не к partial-search pruning и не к choice model;
  - прямое соединение определяется как complete connection с transfer_count = 0;
  - параметр хранится в CompleteConnectionDominanceConfig как deactivate_dominance_of_direct_connections;
  - при deactivateDominanceOfDirectConnections = 1 прямое полное соединение не должно доминировать другое полное соединение;
  - параметр читается из root.searchPara.deactivateDominanceOfDirectConnections и протягивается через AssignmentRuntimeParams/AssignmentInput в search pipeline;
  - парсер валидирует CompleteConnectionDominanceConfig через validate_complete_connection_dominance_config;
  - complete_connection_dominates(config, lhs, rhs) и retain_exact_complete_connection(..., config) поддерживают эту политику в обе стороны retention-проверки;
  - suffix lower-bound pruning использует тот же complete_connection_can_dominate(config, complete), поэтому прямое найденное соединение не отсекает частичную ветвь по lower-bound dominance при активном флаге;
  - диагностика выводит complete-connection dominance config и parser/runtime значение deactivate_direct_dominance;
  - duplicate trace rejection остается отдельной канонизацией одинакового соединения и не является behavioral dominance.

Семантика veh_journey_item_cap.csv и post-assignment overload assessment:

  - файл veh_journey_item_cap.csv является необязательным входом pair-file режима;
  - ожидаемые колонки: _VEHJOURNEYID, INDEX, TOTALCAP, SEATCAP;
  - _VEHJOURNEYID маппится в TripId, INDEX маппится в RoutePosition/from_index;
  - ключ провозной способности vehicle journey item: (trip_id, from_index);
  - TOTALCAP используется как общая провозная способность для оценки перегрузки;
  - SEATCAP сохраняется как аналитический атрибут и не используется как критерий перегрузки без отдельной политики;
  - пассажирская поездка ride-leg с trip_id = t, from_index = i, to_index = j занимает строго полуинтервальный набор vehicle journey items [i, j), то есть (t, i), (t, i + 1), ..., (t, j - 1);
  - конечный to_index не включается, поэтому terminal item с нулевой capacity не должен получать нагрузку только из-за высадки на последней позиции;
  - после split результат DemandSplitResult проецируется в VehicleJourneyItemLoads: для каждой положительной доли спроса и каждого ride-leg пассажиры добавляются ко всем occupied items;
  - validation проверяет сохранение пассажиро-элементной суммы: sum(item_loads) = sum(share.passengers * occupied_item_count);
  - overload assessment строится на полном отчетном support: все пары (time interval, capacity row) плюс нагруженные items без найденной capacity;
  - строки capacity-файла с нулевой нагрузкой материализуются в AssignmentOutput.vehicle_journey_item_loads с passengers = 0;
  - нагруженные items без capacity сохраняются отдельными строками со статусом missing_capacity;
  - сопоставление item-loads с capacity выполняется по ключу (trip_id, from_index);
  - для найденной capacity рассчитываются load_factor = passengers / TOTALCAP и overload_passengers = max(0, passengers - TOTALCAP);
  - статусы строк overload: ok, overloaded, missing_capacity, zero_capacity;
  - если файл capacity отсутствует, AssignmentOutput.vehicle_journey_item_loads получает status = missing_capacity_input и строки не формируются;
  - если basePara.calcAssign = False, AssignmentOutput.vehicle_journey_item_loads получает status = skipped_assignment_disabled и строки не формируются;
  - если compile-time override TIMETABLE_OVERRIDE_DISABLE_VEHICLE_JOURNEY_ITEM_OVERLOAD_ASSESSMENT активен, AssignmentOutput.vehicle_journey_item_loads получает status = disabled_by_config и строки не формируются;
  - assignment_output.json содержит секцию vehicle_journey_item_loads со status и entries;
  - файловый экспорт содержит отдельный primary-файл elementary_segment_loads.csv с колонками interval_id, trip_id, from_index, passengers;
  - vehicle_journey_item_loads.csv является overload/capacity assessment над elementary_segment_loads.csv и содержит колонки interval_id, trip_id, from_index, passengers, total_capacity, seat_capacity, load_factor, overload_passengers, status;
  - stop_loads.csv содержит остановочные агрегаты: boarding_passengers, alighting_passengers, transfer_boarding_passengers, transfer_alighting_passengers, incoming_passenger_segments, outgoing_passenger_segments, through_passengers, stop_turnover_passengers, transfer_passengers;
  - loads.csv остается таблицей линейных, маршрутных, рейсовых и сегментных нагрузок, а остановочные агрегаты вынесены в отдельный stop_loads.csv, чтобы не смешивать разные уровни агрегации.

Связь с volCapRatioFactor:

  - SearchImp.volCapRatioFactor и PerceivedJourneyTime.volCapRatioFactor теперь читаются из params.txt и хранятся в доменной модели параметров;
  - SearchImp.volCapRatioFactor применяется в capacity-aware search только при search_mode = enabled:
      search_impedance'(c, L) = search_impedance(c) + volCapRatioFactor * capacity_exposure(c, L);
  - search_mode = stored_only означает, что SearchImp.volCapRatioFactor прочитан, провалидирован и сохранен, но не изменяет search impedance и не запускает внешний assignment-loop;
  - search_mode = enabled означает behavioral capacity-aware assignment: на каждой внешней итерации заново выполняется search -> choice -> split -> vehicle journey item load projection -> MSA update;
  - baseline assignment — это обычный timetable branch-and-bound search/choice/split без влияния загрузки на search impedance; stored_only сохраняет baseline-поведение даже при положительном SearchImp.volCapRatioFactor;
  - behavioral capacity-aware assignment вычислительно существенно дороже baseline assignment, потому что внешний fixed-point loop может выполнять branch-and-bound search несколько раз, а не один раз;
  - для capacity-aware search загрузки VehicleJourneyItemLoadState фиксируются на всю search-итерацию; это сохраняет корректность dominance и suffix lower-bound, потому что branch-and-bound оптимизирует одну фиксированную функцию стоимости;
  - suffix lower-bound для capacity-слагаемого в branch-and-bound равен 0: для поддержанных penalty policy capacity penalty неотрицателен, поэтому нулевая нижняя оценка допустима; более сильная граница не используется, пока она не доказана отдельно;
  - PerceivedJourneyTime.volCapRatioFactor хранится как PerceivedJourneyTimeWeights.volume_capacity_ratio и применяется в capacity-aware split:
      capacity_exposure(c, L) = sum_e ride_time_e * phi(load_e / capacity_e),
      PJT'(c, L) = PJT(c) + volCapRatioFactor * capacity_exposure(c, L);
  - capacity-aware split решается итерационно на фиксированном множестве выбранных альтернатив: split -> vehicle journey item loads -> MSA update -> повторный split;
  - если включен capacity-aware search, используется внешний assignment-iteration слой: fixed load state -> search -> choice -> split -> vehicle journey item load projection -> MSA update;
  - при включенном capacity-aware search отдельный iterate_capacity_aware_split не вкладывается внутрь search-режима; split оценивается один раз на фиксированном состоянии текущей внешней итерации;
  - если SearchImp.volCapRatioFactor > 0, runtime требует либо включенный capacity-aware search, либо явный режим stored_only; parser params.txt по умолчанию выбирает stored_only для положительного SearchImp.volCapRatioFactor, чтобы чтение параметра не меняло baseline-режим алгоритма;
  - если включен behavioral capacity-aware режим через SearchImp.volCapRatioFactor или PerceivedJourneyTime.volCapRatioFactor, pipeline требует загруженный veh_journey_item_cap.csv; при отсутствии capacity input расчет завершается ошибкой вместо молчаливого игнорирования capacity-aware режима;
  - validation behavioral capacity-aware assignment проверяет, что для каждого используемого ride item существует запись capacity и TOTALCAP > 0; zero capacity остается допустимым статусом только для post-assignment overload assessment, но не для behavioral search/split;
  - результат capacity-aware iteration валидируется как обычный split, а также проверяется корректность half-open проекции split -> vehicle journey item loads, конечность load state и согласованность diagnostics с max_iterations и заданными tolerance;
  - JSON output schema = timetable.assignment_output.v12 содержит metadata.capacity_aware: capacity_aware_enabled, capacity_aware_search_enabled, iterations, converged, max_load_delta, used_factor, penalty_policy; по сравнению с v11 в секцию loads добавлен массив elementary_segment_loads как primary load profile;
  - iterations, converged и max_load_delta относятся к общему outer assignment-loop при capacity_aware_search_enabled = true и к split-only fixed-point loop при capacity_aware_search_enabled = false;
  - search diagnostics логирует search cost mode, номер внешней capacity-aware итерации, размеры capacity index и wall-clock heartbeat долгих batch/branch, чтобы отличать вычислительно тяжелый search от зависания процесса;
  - metadata.csv сохраняет прежние колонки и не содержит capacity-aware diagnostics; новые остановочные показатели вынесены в отдельный stop_loads.csv;
  - used_factor в metadata.capacity_aware равен максимальному из поведенчески примененных SearchImp.volCapRatioFactor и PerceivedJourneyTime.volCapRatioFactor.
